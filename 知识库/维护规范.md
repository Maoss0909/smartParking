# 知识库维护规范

## 资料可信度分级

| 等级 | 来源 | 写法 |
| --- | --- | --- |
| A | 已登录测试环境实测，且有截图或 JSON 记录 | 可写为“页面显示”“实测可见”“测试环境确认”。 |
| B | 已有 Markdown 手册、截图和用户确认内容 | 可写入用户手册，但应保留“不推断未展示规则”的边界。 |
| C | 只在菜单或按钮中出现，未进入完整流程 | 只能写“存在入口”或“页面可见”，不能写结果和业务影响。 |
| D | 口头推测、代码外推、未验证经验 | 不写入正式知识库；如重要，放入待确认问题。 |

## 文件职责

- `停车收费系统用户手册.md`：当前可对外工作版。
- `index.html`：由用户手册生成的客户演示页。
- `知识库/页面知识库.md`：由页面实测 JSON 生成，主要服务内部查询。
- `知识库/业务规则库.md`：人工维护，只记录确认过的业务规则和待确认项。
- `版本管理/用户手册/版本记录.md`：记录每个用户手册版本的时间、变更、截图校验和校验值。
- `版本管理/用户手册/实测记录/`：保存测试环境页面采集 JSON。

## 更新规则

1. 页面字段变更时，先更新页面知识库，再判断是否需要同步用户手册。
2. 业务规则变更时，必须写清楚来源，例如“测试环境页面实测”“用户确认”“已有资料”。
3. 未完整验证的功能，不写生效机制、金额影响、权限边界和后台任务结果。
4. 新增截图时，只提交本次新增且被文档引用的截图。
5. 原始 Obsidian 资料目录继续保持本地 ignored，不进入 Git。

## Git 提交流程

1. `git status --short --ignored` 确认原始资料目录仍为 ignored。
2. 精确 `git add` 本次修改文件。
3. `git diff --cached --name-only` 检查提交范围。
4. 运行必要校验，例如截图引用缺失检查、HTML 生成检查。
5. 提交并推送。

## 命名约定

- 页面知识库按后台模块分组：停车中心、订单中心、运营中心、系统中心、个人中心、封闭车场。
- 截图文件名采用“模块-页面-用途”的中文名称。
- 版本目录使用 `V1.0`、`V1.1`、`V2.0` 格式。
